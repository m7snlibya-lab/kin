The design verdictThe earlier design had better visual rhythm.

The latest version solved legibility, but too many equally prominent controls and nested boxes made it feel like a form. The right move is to recover the earlier hierarchy while preserving the accessibility improvements.

02 / The diagnosis

Readable had become visually heavy.

01 — HIERARCHY

Everything asked for attention.

The hero held Add, Import, Share, Ages & dates, and Export. The page then repeated a section heading, layout picker, navigation, search and filtering before showing a person.

Implemented: Two hero actions, a compact utility toolbar, a clearer active tab, and search, view and filter controls grouped together.

02 — DENSITY

The cards became long forms.

Two filled boxes inside every card, bold age phrases, separate lines for months and days, and repeated borders created bulk. The earlier cards were compact but their secondary text was too small.

Implemented: Open columns divided by one rule; large numerals, quieter units; inline month/day detail; 15–16 px supporting card text.

03 — PERSONALITY

The family feeling receded.

Uniform purple avatars and cool boxes flattened the page. Hiding the next birthday below the entire family removed a useful reason to return.

Implemented: Warm paper, varied initials, plum Gregorian and sage Hijri numerals, and an actionable next-birthday summary.

03 / Small screens and Arabic

One experience, with room to read.

The phone layout has labeled controls, no floating button over the family, and no essential information that depends on hovering.

These review screenshots intentionally disable the service worker to make historical comparisons reproducible; the “Offline setup unavailable” footer in the captures is a capture condition. Real offline behavior is tested separately with the worker enabled.

Type and spacing

A serif headline provides character. Familiar system fonts handle tasks and numbers without new font downloads. Card names lead; age numerals dominate; secondary dates remain readable. The existing Larger text control is remembered, and narrow screens stack the calendars in that mode.

Interaction and trust

Both calendars stay explicitly labeled: color is supplementary. The birthday shortcut clears restrictive agenda settings so the announced event can be found. Empty-filter feedback no longer asks an existing family to add its first person. Import remains available on an empty installation.

06 / What I would do next

Validate the human side before adding more.

First: observe real use

  1. Test with younger and older family members. Ask them to add a person, read both ages, identify the next birthday, and export a calendar. Observe mistakes and hesitation before explaining.
  2. Check the sharing mental model. Ask whether an old family link changes when someone edits a date. If people expect synchronization, improve the sharing explanation before adding features.
  3. Validate on actual phones. Include iPhone/Android, Arabic system language, large system text, screen readers, and a real printed calendar.

Then: targeted improvements

For large families, consider a denser card option only if scrolling proves costly. A relationship view could be valuable, but first define how relationships are entered and maintained. For low-vision users, prioritize screen-reader and magnification findings over another visual theme.

My recommendation

Keep this direction: a quiet, personal family space. Do not grow the main screen into a dashboard of every available feature. New tools should earn their place through observed need.
